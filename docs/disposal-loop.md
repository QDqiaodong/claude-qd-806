# 环境越限处置闭环（验收说明）

## 状态机

```
连续3条越限读数                连续6条适宜读数                 值班员确认
读数上报 ───────▶ 待接单 ─接单─▶ 处理中 ──────────────▶ 恢复待确认 ───────▶ 已解除
                   │              ▲                        │
                   │              └──── 确认前再次越限 ─────┘（退回处理中，重新累计6条）
                   └────────────── 活动单（每菇房至多1张，DB 唯一索引兜底）
```

- 活动单 = 待接单 / 处理中 / 恢复待确认；`environment_disposal_order(room_id, active_flag)` 唯一。
- 已解除单 `active_flag = NULL`（MySQL 唯一索引允许多个 NULL），同一菇房可再次触发新单。

## 核心规则落地

| 需求 | 实现 |
| --- | --- |
| 连续三条（按采集时间）越限才开单，只开一张进行中处置单 | 上报事务先 `SELECT ... FOR UPDATE` 锁菇房，取按 `recorded_at` 升序窗口判断“末尾连续越限≥3”；唯一索引兜底 |
| 保留触发指标与读数 | 处置单存 `trigger_metrics/temperature/humidity/co2_ppm/recorded_start/end`；读数关联表保存 TRIGGER 三条 |
| 仍在生产的出菇批次标“环境暂停” | 暂停时快照批次原状态到 `environment_disposal_batch`；状态为已结束/环境暂停/人工暂停的批次不动 |
| 迟到/乱序读数不误触发、不重复开单、不冲掉较新判断 | 全部判断以采集时间有序序列为准：开单只认“当前越限后缀”，恢复只认“最近6条全适宜”；补历史缺口的读数进不了当前后缀；六连窗口内乱序插入越限会退回处理中 |
| 重复上报同一读数 | 同菇房+同采集时间+同值 → 幂等返回原读数 ID，不重复开单/累积；同采集时间不同值 → 拒绝（不覆盖历史） |
| 接单（预计完成时间+处理记录） | `POST /{id}/accept`，条件 UPDATE 原子抢占（`assignee IS NULL`），两人并发只一人成功 |
| 异常继续恶化累积到原处置单、保留经办轨迹 | 新越限读数挂 OVER 关联、累加 `over_count/last_over_*`，产生“持续越限/恶化”事件，事件永不修改只追加 |
| 连续六条恢复到齐 → 恢复待确认 | 处理中时最近6条（按采集时间）全部适宜才进入，RECOVERY 关联每次对账幂等重建 |
| 确认前再次越限退回处理中 | 恢复待确认时最近6条任一越限（含乱序插入）即退回，删除 RECOVERY 关联、计数清零、留“再次越限退回”事件 |
| 解除只恢复本单暂停的批次 | 仅对快照中当前仍为“环境暂停”的批次 `UPDATE ... WHERE status='环境暂停'` 还原原状态；已结束/人工暂停不改；记录 `restored_at` |
| 完整时间线 | 触发/接单/处理记录/持续越限/恶化/恢复待确认/再次越限退回/解除 全部入 `environment_disposal_event`，带操作人与读数引用 |
| 状态一致 | 环境仪表盘、菇房总览、出菇批次列表均 LEFT JOIN 活动处置单；前端 15s 轮询，处置抽屉按最新数据渲染 |

## HTTP 接口

- `POST /api/environments` 上报读数（body 同原环境记录，`recordedAt` 可空=当前时间）
- `GET  /api/environment-disposals?status=&roomId=` 处置单列表
- `GET  /api/environment-disposals/active` 活动单简报
- `GET  /api/environment-disposals/{id}` 详情（单+批次快照+时间线+关联读数）
- `POST /api/environment-disposals/{id}/accept`   `{operator, expectedFinishAt, note}`
- `POST /api/environment-disposals/{id}/progress` `{operator, expectedFinishAt?, note?}`
- `POST /api/environment-disposals/{id}/resolve`  `{operator, note}`（仅恢复待确认可解除）

## 建议手工验收序列（GR-A01 金针菇，适宜 4~12℃ / 85~95% / CO₂≤1200）

1. 仪表盘对 GR-A01 连续“上报读数”3 次越限（用“填入越限读数”，采集时间留空）→ 出现待接单处置单，批次 FB-260915-05 变“环境暂停”。
2. 用 A 值班员接单填预计完成时间；B 值班员同时接单 → 一人成功一人收到“已被接走”。
3. 再上报越限读数 → 原单“持续越限/恶化”累积，不产生第二张单。
4. 连续上报 6 次适宜读数 → 处置单进入“恢复待确认”；此时直接解除前，补报 1 次越限 → 退回处理中；再补 6 次适宜 → 恢复待确认。
5. 乱序验证：恢复待确认时，用“过去的采集时间”上报一条越限（时间落在最近6条窗口内）→ 立即退回处理中；用更早、不在窗口/后缀内的时间上报 → 不触发任何状态变化。
6. 确认解除 → FB-260915-05 恢复为“待采收”；二潮结束等其它批次不受影响；时间线完整可查。
